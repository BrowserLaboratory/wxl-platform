# Domain Reference：資訊安全（Information Security）

---

## 1. 概述

本 domain reference 適用於以 Phoenix 風格撰寫**資訊安全（Information Security）**領域的科普文章。當文章主題涉及網路安全、滲透測試、密碼學、數位鑑識、社交工程、惡意程式分析等資安相關主題時，應載入此檔案作為領域特化指引。

載入後，本檔案將客製化 Concept Escalation 的 Step 7（情境框架）和 Step 9（動手實作），並擴充 SKILL.md 的修辭手法和收尾語選項。

## 2. 情境框架實現（Contextual Framing Implementation）

<!-- 此段落實現 Concept Escalation Step 7 的資安領域特化 -->

### 三個倫理反思問題（逐字版）

在教授任何攻擊性技術前，或章節結尾的倫理框架中使用。必須完整呈現，不可縮改：

```markdown
因此，想問即將踏上這條路的你三個問題：

如果全世界都知道我在做這件事，我還會做嗎？

我做這件事是為了學習，還是為了利益/炫耀？

這件事會傷害到誰嗎？
```

### 法律後果錨定（Legal Consequence Anchoring）

在教授攻擊性技術前，必須先建立法律後果框架：

- 引用具體 ROC 刑法條文（如刑法第 358 條「無故入侵電腦罪」、第 359 條「無故取得電磁紀錄罪」等）
- 使用法庭對話模板（見下方）戲劇化呈現法律後果
- 結尾以：「法律可不管你是『好奇』、『學習』還是『測試』」收束

**ROC 刑法引用慣例：**
- 首次引用：完整條號 + 罪名 + 法律效果
- 後續引用：簡稱即可（如「前述第 358 條」）
- 引用格式：「依據我國刑法第 N 條，〔罪名〕，處〔刑罰〕」

### 法律框架法庭對話模板

用於倫理/法律章節，以戲劇化方式呈現法律後果的真實性：

```markdown
你可以想像當你做了某種「測試」然後被刑事局請去喝茶，最後到了法官面前：

（👨‍🦳法官；🤡你）

🤡：法官大人，我只是想〔理由〕...
👨‍🦳：所以你承認未經授權〔行為〕了？
🤡：啊... Σ(ﾟДﾟ；≡；ﾟдﾟ)
👨‍🦳：本席判你有罪！下一位～

你可能會想：「哎呀，哪這麼嚴重！」但〔具體法條/後果說明〕。
```

**使用規則：**
- 只在第一次介紹法律風險時使用，不要每節都用
- 法庭對話後必須立即接具體法條或行為分類表
- 嚴肅的法律結果說明之後才是幽默，不是相反

## 3. 動手實作格式（Hands-on Practice Format）

<!-- 此段落實現 Concept Escalation Step 9 的資安領域特化 -->

### CTF 練習題格式（7 必填欄位）

題目名稱 / 題目說明 / 目標網站網址（含安全警語）/ 任務目標 / flag 格式 / 任務預計時間 / 提示

### CTF 練習題模板

所有 CTF 實踐題目必須包含以下七個欄位，缺一不可：

```markdown
CTF 實踐：〔練習主題〕

**題目名稱：** 〔題目標題〕

**題目說明：** 〔2–3 行，說明這個網站/系統的背景情境，不要直接洩題〕

**目標網站網址：** 〔URL〕（請認明網址，只有在這個網址開頭的才是你的目標）

**任務目標：** 請想辦法〔說明需要達成什麼目標，如：取得 flag〕

**flag 格式：** FLAG{\S}（若不確定，可貼到 https://regex101.com/r/8qUgYm/1 確認）

**任務預計時間：** 〔N〕 分鐘（超過沒關係，第一次我懂 ╮(╯∀╰)╭ ）

**提示：** 〔一個暗示性但不洩題的線索，描述解法的思路方向，而非答案〕
```

**注意：**
- 提示只給方向，不給答案：「如果能把 X 變成 Y，是不是就可以...？」
- 時間估計通常設定為 10–15 分鐘，後接帶顏文字的同理心說明
