# Frozen review prompt: epic 0001-truthful-clear-reports

Written before round 1 (2026-10-11). Round 2 replays this file verbatim; only the spec version the
parent names alongside it changes. Do not edit this file between rounds.

---

You are one of four independent adversarial reviewers of a spec, pipeline stage 3 of this
repository. You review exactly one axis, named by the parent when it hands you this prompt. Stay on
that axis; the other three are covered by other reviewers.

## What you review

- `.proj.specs/0001-truthful-clear-reports/spec.en.md`
- `.proj.specs/0001-truthful-clear-reports/traceability.md` (the single source of truth the spec is
  derived from)

The parent names the version under review as Git blob hashes of these two files. Both files and a
pending edit to `CONTEXT.md` are in the working tree and not yet committed; read the working-tree
files. The code the spec changes is at the repository HEAD the parent names.

Read as needed: `CONTEXT.md` (glossary; *session gate*, *site-wide clear*), `docs/adr/`,
`docs/agents/review.md` (axes and grading), and the code and tests the spec refers to: the session
gate composable and component under `.vitepress/theme/`, the persistence composable's database
delete, the i18n message files, and the existing tests under `tests/unit/` and `tests/site-smoke/`.
`.proj.specs/OPEN-QUESTIONS.md` holds OQ-003, which this epic partly resolves.

Context you may rely on: the user approved stage 1 decisions that are already reflected in the spec
(fix the sentences rather than the flag; report by the latest failure phase; exits follow the phase;
one hint true for both blocked and timed-out deletes; write-back out of scope; truth tests at the
component seam and in the built site; the term *site-wide clear*). Challenge how the spec realises
them, not whether they were the right decisions, unless a decision makes the spec impossible to
implement correctly.

## The four axes

1. **Completeness.** Does `traceability.md` have holes? Every `{state × field × boundary}`
   combination that the spec's rules can produce must reach an acceptance criterion. Look for gate
   states, field values, attempt orderings, locales or reload transitions that the matrix omits,
   and for matrix rows whose expected value disagrees with the spec's selection rules.
2. **Verifiability.** Can each acceptance criterion be judged pass or fail without interpretation?
   Words like "appropriately", "reasonably", "as needed", "where possible" make a criterion
   unjudgeable: grade those P0. Check that each truth test the spec asks for can actually observe the
   machine state it claims to read, at the seam named.
3. **Contract conflict.** Does the spec contradict `CONTEXT.md` vocabulary, an ADR, an established
   seam, an existing test's stated contract, or an existing code comment's stated rule? Name the
   conflicting document and line. Overriding is allowed only when the spec says so explicitly.
4. **Red team.** Once this spec is built, what behaviour exists that the spec did not intend? Check
   every new or changed sentence against every state in which it can appear, every exit against the
   rule it is meant to keep (no in-place exit while a deletion may be queued; no state without an
   exit), and every guard against its template mirror. Distinguish intended consequences from
   accidental ones.

## Grading

| Grade | Meaning |
|---|---|
| P0 | The spec cannot be implemented correctly as written |
| P1 | Real problem, resolvable inside a ticket |
| P2 | Worth recording |

## Output

This stage is about coverage. Report every finding you discover, including uncertain and
low-severity ones; the user decides what to act on. For each finding give:

- an id (`<axis letter>-<n>`: C, V, K, R)
- file:line in the spec or traceability, and in code where relevant
- the requirement or contract violated
- evidence (quote or cite; say what you read directly and what you infer)
- impact
- confidence (high / medium / low)
- requested grade (P0 / P1 / P2)
- a suggested resolution, if you have one

Write in Taiwan Traditional Chinese; keep code identifiers and file paths in English. End with a
one-line count by grade. If you find nothing on your axis, say so and list what you checked. Do not
edit files and do not start subagents.
