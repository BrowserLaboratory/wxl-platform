# Spec 0001：全站清除的回報要說真話

狀態：v3。第 3 階段在第 2 輪以零 P0 通過（`review/round-2.md`）。v3 納入使用者的裁決 A1–A5 與第 2 輪的
P1 發現，沒有再送審。本文引用的每條規則與每一列，以 [`traceability.md`](traceability.md) 為準。用語見
`CONTEXT.md`（*解題紀錄沿用確認*、*全站清除*）與 `traceability.md` 開頭的名詞表。本檔由英文版翻譯，
以英文版為準。

## 問題

在共用電腦上，解題紀錄沿用確認會問眼前的人：已存的紀錄是不是你的，並提供「刪除並重新開始」，也就是
全站清除。一次清除做到一半停下來時，gate 會回報發生了什麼。有三條路徑上的回報是假的。

- **K2**：刪除資料庫成功，接著掃除 localStorage 失敗。gate 說已存的紀錄「已經刪掉，而且救不回來了」；
  但資料庫裡可能根本沒有學習者的資料，學習者唯一的作品（`localStorage` 裡的一份筆記草稿）還完整留著。
  2026-10-10 在正式站上讓 `removeItem` 拋錯後重現。
- **K3**：在同一條路徑上，gate 用那句假話來解釋為什麼「沿用」不見了、為什麼出現「關掉這則說明」。
  收回「沿用」本身是對的（清除已經開始），畫面上給的理由不對。
- **K4**：掃除失敗後，學習者照提示再按一次刪除。這次會先刪資料庫；如果有一條不肯讓開的連線占著，刪除
  會被擋住。gate 仍然顯示掃除失敗的說法（「關掉其他分頁也不會把它們刪掉」），旁邊卻印著原始錯誤
  「another tab still has it open」，而且在刪除可能還在排隊時，提供原地繼續。2026-10-10 在正式站上用
  第二個分頁開一條原生連線後重現。

嚴重度：罕見路徑上的回報不實，沒有任何路徑會遺失資料。真實瀏覽器裡，掃除只會因為瀏覽器實作自己加的
檢查而拋錯（例如 Firefox 在頁面開著時關掉 `dom.storage.enabled`、Safari 在頁面卸除那一刻）或擴充套件；
HTML Standard 對 `removeItem`、`key()`、`length` 沒有定義任何拋錯步驟。K4 更罕見：本站自己的連線收到
`versionchange` 會自動關閉，所以開著現行版本的另一個分頁不會擋住刪除；只有還在跑舊版程式的分頁，或其他
不肯讓開的連線才會。

根因：gate 記的是「刪除資料庫回來了」，而每一句讀它的話都說成「學習者的作品沒了」。讀同一個狀態的
守門邏輯需要的正是它記的事實，錯的只有那些句子。回報與出口也只看這個狀態來分支，所以後一次失敗會被
當成前一次來回報。另外，「沒能開始」的那次清除還會抹掉「刪除可能仍在排隊」這筆紀錄。

## 解法

gate 繼續記錄刪除資料庫何時回來，但改用名實相符的名稱，並記下最近一次已開始的清除是在哪一半失敗。
學習者看到的內容由這些事實決定：

- 掃除失敗後，gate 說資料庫已刪除、其他項目沒能全部刪掉，不聲稱資料庫裡原本有東西，也不聲稱是誰的。
  提示說再按一次刪除，會把整個全站清除重試一次。
- 刪除資料庫沒完成時（不論是第幾次），gate 回報結果無法確認，出口給整頁重新載入，提示對每一種刪除失敗
  都成立。
- 因為無法記下「已經開始」而沒能開始的那次清除，只在前一次留下的報告下方加一句說明，其他都不動。
  前一次的報告仍然看得到，按之前不安全的出口，按之後也仍然不會出現。
- 每一句改過的話都由測試釘住：測試先把機器擺成這句話所描述的狀態，再比對字面文字。

## 使用者故事

1. 身為在共用電腦上、清除停在資料庫已刪除之後的學習者，我希望 gate 說出刪掉了什麼，但不聲稱我的作品被毀
   了，這樣我不會誤以為失去了其實還在機器上的作品。
2. 身為後一次清除被擋住的學習者，我希望 gate 回報的是被擋住的刪除，而不是前一次的掃除失敗，這樣它建議
   的補救才真的有用。
3. 身為刪除可能還在排隊的學習者，我希望唯一的出口是整頁重新載入，這樣我不會繼續在一個記憶體中的紀錄可能
   被寫回的頁面上作答。
4. 身為刪除逾時、或在沒有其他分頁的情況下失敗的學習者，我希望提示不要說有其他分頁開著，這樣我不會去找一個
   不存在的分頁。
5. 身為重試連開始都沒能開始的學習者，我希望知道這次什麼都沒刪、該怎麼處理，而且 gate 不會忘記前一次留下
   的狀態。
6. 身為維護者，我希望這個 epic 改過的每一句 gate 文字都有測試對照它描述的機器狀態，這樣把它改成假話時，
   測試會變紅。

## 實作決定

**gate 的狀態（seam S1：session gate composable 回傳的物件）**

- `storedWorkGone` 改名為 `databaseDeleted`，語意不變（module-level；從這份文件裡刪除資料庫回來的那一刻
  起為真，在同一份文件裡不會重設）。不保留舊名稱的別名，程式碼與測試裡都不再出現舊識別字。（T1–T4）
- 新增 `clearFailurePhase`，module-level，跟錯誤狀態放在同一層，定義見名詞表：清除開始時為 `null`；任何
  刪除被拒時為 `'delete'`；掃除拋錯時為 `'sweep'`。（T5–T10）
- 新增 `clearRefused`，module-level：有前一次狀態的清除沒能開始時為真；清除開始時、以及新文件裡為假。
  （T10d、T10e）
- **刻意改變現有行為**：有前一次狀態的清除沒能開始時，`clearFailurePhase`、`clearStarted`、錯誤都不動，
  只設定 `clearRefused`。現行程式在這時會把 `clearStarted` 設成 false，並取代錯誤。第一次清除就沒能開始
  （沒有前一次狀態）時，行為跟現在一樣，「沿用」仍然提供。（T9、T10a–T10g）
- 清除進行中再按一次會被忽略，什麼都不改變（維持現狀）。（T10c）
- 「沿用」與「關掉說明」由 composable 把關，template 只是對照呈現，規則見 `traceability.md`。後一次清除
  仍然先刪資料庫再掃除。只要任一旗標為真、或問題還沒回答，解題進度就繼續擋住。（T11–T16a）

**gate 顯示什麼（seam S2：以真的 composable 渲染 gate 元件）**：說明、報告、原始錯誤行、「沿用」、
「重新載入」、「關掉說明」，以及在非題目頁是否顯示，都依 `traceability.md` 的選擇規則表，由上往下比對。
簡單說：報告依最近一次已開始的清除失敗在哪一半；有前一次狀態的清除沒能開始時，在那份報告下方加一句重試
提示；畫面上有錯誤或沒能開始的說明、清除開始過、而且最近的階段不是掃除時，出現「重新載入」；只有畫面上有
錯誤、而且最近的階段是掃除時，才出現「關掉說明」；規則沒有點名的錯誤，一律落到「結果無法確認」的報告，
這份報告不提供「關掉說明」。（T17–T29s）

**文案**：五句，兩種語言，完全照 `traceability.md` 的文案表：改寫四句（`body_cleared`、`sweep_failed`、
`sweep_failed_hint`、`clear_unconfirmed_hint`），新增一句（`clear_retry_not_started_hint`，有前一次狀態的
清除沒能開始時，加在前一次的報告下方）。五句都不含禁用詞（CI-1）。沒改、但預設有已存紀錄的句子（包括
標題）是明示的取捨（CI-2）；在 gate 沒有偵測證據也會發問的兩條路徑上，這個預設沒有證據撐著，這是既有
行為，由一條新的 open question 追蹤。新句子在指稱這個動作時，依 `CONTEXT.md` 使用「全站清除」。

**註解與測試**：T38、T39 列出的每一處註解與測試，都要跟這些規則一致。清單以 `72327e2` 為準；實作期間位置
移動時跟著移。

**詞彙表**：`CONTEXT.md` 新增「全站清除」（第 1 階段），以概念層定義，宣告保留的偏好不在範圍內。介面字串
第一次出現「全站清除」的那個改動裡，要同時拿掉它的「新造詞」宣告，詞彙表測試才會維持綠燈。（T43）

**Open questions**：OQ-003 維持 open，並逐一列出本 epic 以字面比對釘住的內容；OQ-001 記錄它的重新檢視條件
已經觸發、以及重查的結果；新增兩條，分別記錄記憶體中紀錄的寫回，以及 gate 固定句子預設有已存紀錄，證據都
直接寫在條目裡。（T40–T42、T44）

## 測試決定

好的測試從 gate 外面觀察行為：composable 對外露出的狀態、元件渲染出來的文字與控制項、真實瀏覽器裡的頁面。
不斷言私有輔助函式，也不斷言呼叫順序。

- **S1，composable**：在既有的 composable 測試裡補上 T1–T16a。前例：composable 自己的測試檔，以及
  unconfirmed-clear 測試檔。
- **S2，真話測試（新 seam）**：用真的 composable 和真的資料持久層（fake-indexeddb）掛載 gate 元件。每個
  狀態只用它所列的錯誤注入（F1–F6）來造。每個真話測試先斷言真話矩陣裡的前置條件（只用 `traceability.md`
  允許的方式讀資料庫），再把每一句渲染出來的文字，跟測試裡寫死的字串做完全相等比對，en 與 zh-TW 都要。
  不只真話列，每一個 S2 測試都這樣比。替換刪除用的物件必須是真的 `IDBRequest`，每個注入在它針對的那一次
  按下之後立刻移除。預期文字一律不從 message 檔匯入，所以把 message 檔改成假話，測試一定會變紅。CI-1 也用
  同一組字面字串檢查。前例：meaningful-stored-work 測試的 fake-indexeddb 流程；unconfirmed-clear 測試在
  `finally` 裡還原 storage 替身的做法。
- **S3，建置後的網站**：在 site smoke 套件裡加兩個 Playwright 情境，對 production build、英文語系、題目頁
  `door-is-open`：T36（K2）與 T37（K4）。第二個頁面先到網站根目錄，再用 `page.evaluate` 開一條原生連線，
  這條連線不會讓開。句子用 `toHaveText` 比對，不用 `toContainText`。只有 T37 需要等過刪除的時限。前例：
  gate-scope smoke spec，它用 `addInitScript` 預先放好證據。
- 計時依 `traceability.md` 錯誤注入表下方的說明。
- 既有的 gate 元件分路測試保留，mock 補上 `clearFailurePhase` 與 `clearRefused`，T38 列出的案例改寫。

## 不在範圍內

- 掃除失敗後、或寫入標記到重新載入之間，記憶體中紀錄的寫回（T41）。
- 上述五句以外的 session gate 文案，以及 OQ-003 其餘部分。
- 在提示裡區分「被擋住」「逾時」「其他」三種刪除失敗。
- 一直遇到「其他」類型失敗的清除：重新載入的出口會回到同一個 gate。記錄，不處理。
- 清除進行中「刪除並重新開始」仍然顯示（按了會被忽略）；掃除失敗那句話在成功時對被豁免的語系鍵也成立。
  既有行為，記錄。
- 一直沒能開始的清除：重新載入的出口會回到一個再按又沒能開始的 gate，直到關掉分頁為止。記錄，不處理。
- 新文件讀不到「清除已經開始」的紀錄（例如頁面開著時儲存被關掉），會把機器當成沒動過。既有限制，記錄。
- 第一次清除沒能開始，但紀錄其實寫入了、只是讀不回來時，紀錄會留到下一次載入。既有行為，記錄。
- 自訂過 gate 元件的 fork 必須跟著改名；寫進 release note。
- gate 的遮罩與無障礙（OQ-002）。
- 使用指南：沒有引用到要改的字串。把指南的用語統一成「全站清除」是另一件工作。
