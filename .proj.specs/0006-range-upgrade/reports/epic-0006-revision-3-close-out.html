要決定的事

升級功能（create-wxl upgrade）還沒發布。revision 3 讓這個功能補上幾項保護：

  • base 必須是上游的發布版；
  • 名稱別名不會讓檔案被誤刪；
  • 還原不會刪掉被 ignore 的檔案；
  • git 有最低版本要求。

這份報告回答一個問題：這些保護有沒有證據支撐，足以讓 create-wxl 3.1.0 帶著升級功能發布。

證據鏈

  1. 每張 ticket 都先有 test plan，再寫紅燈測試，最後轉綠；確認型測試都做了 mutation 檢查，紀錄在各 ticket。
  2. create-wxl 的測試從 623 個增加到 716 個，每個 PR 的 CI 都跑 macOS、Windows、Ubuntu 三種 OS。
  3. 第 8 階段用打包後的套件，在 macOS 終端機上跑過每張 ticket 的行為。T-0063 照 traceability 完整跑完模擬的步驟 1～6，包括 pnpm build 與還原。
  4. 第 6、7 階段由獨立的 reviewer 執行。每個安全候選都再交給另一個 reviewer 判定是不是誤報。
  5. 收尾的串連分析從三個攻擊者位置各自找鏈，跨界的 low 鏈由 T-0066 切斷。

代價與沒有解決的事

  • git 2.20～2.25 的老師（例如 Ubuntu 20.04）用不了升級。建立靶場時改為收到 CW-W01，git 步驟要自己執行。
  • Windows PowerShell 5.1 不接受 &&，老師要分開執行兩個還原指令。spec 已寫明做法。
  • B4 仍然接受幾種情況：經由資料夾別名到達的新路徑；git 2.26～2.35 的 fsmonitor hook 版本 1；zdiff3 讓 checkout 失敗。
  • 這些情況都沒有實測：WSL /mnt/c、PowerShell、git 2.26～2.35，以及 APFS 上的 NFC 等價名稱。
