## 問題陳述

老師只用英文新增一道題目——`pnpm create:challenge` 與 wxl-create 技巧都是這樣做——發布出去的題目，大部分學生卻打不開。網站會把還沒選過語言的訪客、以及選了繁體中文的訪客，從英文頁導到對應的繁中頁，卻不先確認那一頁存不存在，於是他們落在找不到頁面的畫面。繁中題目清單也不列這一題，所以在清單上同樣找不到（OQ-023，2026-10-24 在一個臨時 GitHub Pages 靶場重現）。

文章也有同樣的缺陷。2026-11-04 在正式網站上，唯一一篇只有英文的文章——攻擊紀錄匯出格式的參考文件——就重現了：沒有存過偏好的訪客、以及偏好是繁體中文的訪客，直接打開那一頁都會落到 404；在那一頁的語系切換按鈕選「繁體中文」也是 404。而且 `/zh-TW/` 路徑的 404 會把繁體中文寫進訪客的語系偏好，選過英文的學習者點了一個壞掉的連結，就失去了自己的選擇。

## 解決方式

網站不再把學習者送到不存在的翻譯。學習者的語言沒有某一頁的版本時，他會留在現有的那個版本上，並看到一行用他的語言寫的說明，附上一個連到他那個語言題目清單的連結。這適用於直接打開網址、語系切換按鈕，以及任何原本會落到找不到頁面的路徑：以 slug 組成的短連結、手改的網址、舊連結，或 GitHub Pages 的 404。

儲存的語系偏好只在學習者自己選擇時才改變：用語系切換按鈕，或打開一個網址帶有語系的頁面——直接打開、經由短連結，或重新整理都算。跟著連結進到另一個語言的頁面、按上一頁，或被網站自己的轉址帶走，都不再改變它。瀏覽器不能儲存這個選擇時，由這個分頁記住。

每個題目清單都列出每一道題目。在清單語言沒有版本的題目，顯示它現有版本的標題與摘要，加上「只有英文」之類的標記，點進去開那個版本。

複製按鈕給出的短連結會標明語言：`/en/c/NNN` 或 `/zh-TW/c/NNN`。每一道題目兩種都有；沒有繁中說明頁的題目，繁中短連結開的是英文頁。`/c/NNN` 與 `/zh/c/NNN` 不再發出，已經印出去的照樣打得開。在這個 epic 裡，`/en/c/NNN` 開英文頁的方式和 `/c/NNN` 一樣，所以語言是繁體中文的學習者，在有繁中版時仍會被帶到繁中版；要等主語系 epic 讓英文有自己的網址前綴之後，它才對每個人都開英文。

## 使用者故事

1. 身為老師，我希望我只用英文寫的題目也出現在繁中清單上，這樣用預設語言的學生找得到它。
2. 身為老師，我希望我發出去的任何題目或文章連結，不論學生瀏覽器存了什麼語言都打得開，這樣我發的連結永遠不會落到 404。
3. 身為學習者，我希望某一頁沒有我的語言版本時，網站用我的語言告訴我，這樣我知道網站沒壞，也知道為什麼這一頁是別的語言。
4. 身為學習者，我希望在以別的語言顯示的頁面上，有路可以回到我那個語言的題目清單，這樣我不會一直讀著我沒選的語言。
5. 身為學習者，我希望我選的語言沒有這一頁時，語系切換按鈕讓我留在原頁，並記住我的選擇，這樣我不會丟掉正在看的頁面。
6. 身為學習者，我希望我的語言只在我自己選擇時才改變——用語系切換按鈕，或打開一個標明語言的網址——這樣跟著連結走、按上一頁，或落在壞掉的網址上，都不會替我換掉語言。
7. 身為老師，我希望我複製的短連結標明語言，這樣上游網站改了主語系之後，它仍然開那個語言。
8. 身為老師，我希望已經印在講義上的 `/c/NNN` 與 `/zh/c/NNN` 繼續打得開，這樣我不必重印。

## 實作決策

- **頁面清單（S2、D3）。** 建置時產生已發布頁面的集合，以不含 base 的路徑、照 `cleanUrls` 的拼法表示，並送到瀏覽器；`pnpm dev`（重新啟動後）與 `pnpm build` 都會產生。頁面抵達以 router 實際渲染的那一頁對應到它的清單項目；not-found 路徑以查詢演算法判斷：解碼一次、拒絕 `//`、`\` 與 `..`、去掉 `.html` 與 `/index`、帶與不帶結尾斜線各試一次，而且永遠不丟例外。判斷頁面存在與否，不發任何網路請求。開著的分頁保留它載入時的清單（文件寫明的限制）。
- **抵達的分類（S1、D11、D16）。** 在任何其他決策之前，先把一次抵達分成：頁面抵達、not-found 抵達（路徑不在清單），或載入失敗（清單內的路徑卻顯示找不到頁面，照樣顯示，其他什麼都不做）。所有關於某一頁的決策都用它的清單項目；轉址與切換的目標都是清單項目，絕不取自網址文字。
- **語系導向（S1）。** 這些決策是純函式，輸入是網址、站台 base、儲存值、頁面清單與 router 的結果：
  - 冷載入導向保留原有規則（只離開不帶前綴的那棵樹、等解題紀錄沿用確認做出決定、用 `replace`），並且只前往清單內的對應頁；否則停留，顯示那一行（決策表 A1–A7）。
  - 語系切換按鈕只在所選語系的對應頁在清單內時才導覽。否則它寫入選擇、停留且不新增瀏覽紀錄、不改網址與介面語系，並立刻顯示那一行。那一行顯示時，選單也提供頁面本身的語系，作為回頭的路。在找不到頁面的畫面上，它前往存在的對應頁，否則只寫入選擇。
  - not-found 抵達在對應頁存在於清單時，由對應頁取代，每次抵達最多一次，經由 router，並在解題紀錄沿用確認做出決定之後。
  - 每個決策都會得出這次抵達「被要求的語系」。S1 自己做的轉址把它帶到落點，下一次抵達就丟棄。
- **寫入偏好（D5、D13、D14）。** 只有語系切換按鈕的選擇，以及冷載入 `/zh-TW/` 底下的已發布頁面（包括經由短連結的轉址或重新整理）會寫入儲存的偏好；後者改在 router 解析之後判斷，不再在 `enhanceApp` 裡。Layout 的 route watcher 照舊依網址設定介面語系，但不再寫入偏好。儲存寫不進去時，語系切換按鈕的選擇記在這個分頁的記憶體裡。
- **只有一個語系選單（D7）。** 移除 `USE_CUSTOM_LOCALE_SWITCHER`、保留它為 `true` 時的做法，預設主題的頁面在導覽列的 slot 使用 `LocaleSwitcher`；題目頁照樣使用 `MergedNav` 裡的那一個。三個內建的翻譯選單（`VPNavBarTranslations`、`VPNavBarExtra` 裡的 translations 群組、`VPNavScreenTranslations`）以不依賴執行期 class 的 CSS 隱藏。
- **那一行（S3、D8、D10、D15、D17）。** 一個只在瀏覽器端渲染的主題元件，每次抵達都重新判斷（只改 hash 或 query 不算抵達）。題目頁上是 `MergedNav` 正下方、runtime 重置橫幅之上的整列橫幅；預設主題頁上放在版面的頂端 slot（`doc-before`、`page-top` 或 `home-hero-before`）。它以被要求語系的訊息檔，呈現那個語系逐字固定的句子與連結，`lang` 設為 `en` 或 `zh-TW`。它不能關閉，也絕不出現在找不到頁面的畫面。冷載入或 not-found 抵達產生的那一行，等解題紀錄沿用確認做出決定；語系切換按鈕產生的不等。
- **各語系的題目資料（S4）。** 每個語系的資料載入器依合併規則回傳每一道題目：以 slug 合併、從現有的說明頁借用欄位（含分類）、缺漏欄位用清單語系的預設值、共同的 `id` 規則，以及新增的 `locale` 欄位。`ChallengeList` 在清單與格狀檢視、`HomeContent` 在最新題目卡片上顯示標記，兩者都以頁面語系解析，所以靜態 HTML 就帶著它；借來的標題與摘要帶著它們語系的 `lang`。只有繁中說明頁的條目，在英文清單上不顯示短連結。
- **題目連結（S5）。** 短連結路徑是 `/<語系代碼>/c/NNN`。`ShortLinkShare` 拿兩個輸入：它自己文字的語系（清單或頁面的語系），以及連結的語系（short mode 用清單或頁面的語系，page mode 用條目所在頁面的語系）。0007 的模式規則（`CF_PAGES`）不變。
- **轉址規則（S6）。** `generateRedirects` 為每一道有英文說明頁的題目寫出四條補零的編號規則，以及四條參數化規則，順序照 schema；題目沒有繁中說明頁、或它的繁中目錄未追蹤或被忽略時，繁中編號規則指向英文頁。只有繁中說明頁的題目——pre-commit hook 與 CI 的樹檢查會拒絕——若仍到了產生器，只得到它的兩條繁中規則。檔頭寫明 Cloudflare 的 2,000 條 static 規則上限帶來的 500 題上限。
- **訊息鍵。** 那一行的句子、連結文字與標記各一個鍵，兩個訊息檔都有。第 6 階段在 diff 上確認沒有其他鍵被改動。
- **被覆寫的契約。** traceability 的表格列出本 epic 刻意改動的每一條既有契約，連同 pin 住它的測試——包括 0007 的 H01、H02、H14、H20、H37、H39、H40，route watcher 的寫入、語系選單只有一個選項，以及內建選單在哪裡被隱藏。每一條只照表上所寫的方式改；第 6 階段拒絕任何其他測試的改動。
- **不變的部分。** `DEFAULT_VISITING_LOCALE` 維持 `zh-TW`（D4）。`create:challenge`、pre-commit hook 的觸發與拒絕條件，以及 wxl-create 都不變。

## 信任邊界與威脅模型

| # | 邊界 | 保護什麼 | 不保護什麼 | 不在模型內 |
|---|---|---|---|---|
| B1 | 建置 → 送到瀏覽器的頁面清單 | 清單只含建置發布的頁面路徑。它沒有增加暴露面：每個建置出來的頁面本來就帶著 VitePress 的頁面 hash map，列出所有已發布頁面 | 沒有新的。原本只想靠網址被找到的頁面從來沒有被藏起來，現在也沒有 | 靜態主機 |
| B2 | 網址 → 學習者被送去哪裡 | 轉址目標一律是站台 base 加上頁面清單的一個項目，並經由 router 導覽，所以構造過的路徑（`//host/…`、編碼的斜線、反斜線、`..`、格式錯誤的編碼）無法把學習者送出站外、送到未發布的頁面，或讓程式出錯（C10、查詢演算法）。query 與 hash 照網址保留，和現在的冷載入導向一樣 | 指名另一個語系真實頁面的路徑，會把學習者送到那裡，這正是用意 | — |
| B3 | 建置出的網站 → 學習者的畫面與剪貼簿 | 同 0007 的 B4：連結文字只來自 `SITE_ORIGIN`、補零的號碼與符合 slug 文法的 slug，經 Vue 的跳脫綁定呈現。那一行是固定訊息 | `SITE_ORIGIN` 指錯網站時，連結仍會開到那個網站（0007 的 D10）。同一個 GitHub Pages owner 底下的靶場共用儲存的偏好（OQ-018）：一個靶場的選擇決定另一個靶場的導向與那一行，雖然不再是 404 | — |
| B4 | 學習者的選擇 → 儲存的偏好 → 導向 | 只認 `en` 與 `zh-TW`；其他值或讀不到儲存都當作沒有偏好。只有學習者的選擇會寫入：語系切換按鈕，以及打開 `/zh-TW/` 底下的網址（D5、D13） | 任何頁面——本站或他站——都能連到 `/zh-TW/` 網址，打開就把語言設成繁體中文；本 epic 內沒有連結能把它設成英文。會改儲存的學習者可以選任一語言，這正是切換按鈕的用途 | — |
| B5 | 解題紀錄沿用確認 → 導覽（ADR-0006） | 這個確認保護的是網站關於已存紀錄的歸屬與陳述是否真實；共用電腦上的前一位學習者不是對手，這個確認是提醒，不是存取控制（ADR-0006）。冷載入導向、not-found 導向，以及它們產生的那一行，都等確認做出決定，和現在的冷載入導向一樣 | 語系切換按鈕產生的那一行不等：選擇是學習者自己的動作，而且這個確認不是 modal（D17）。以及 ADR-0006 已寫明它不保護的一切 | — |

沒有碰到任何題目刻意設計的漏洞，所以 ADR-0005 不適用。

## 驗收標準

- **AC-1** 對一棵 fixture 樹與真實的樹，頁面清單都等於 oracle 的集合（`platform/` 底下、`public/` 與 `shared/` 以外、略過點開頭路徑的每個 `*.md`，照 `cleanUrls` 拼法）；找不到頁面的畫面與非頁面檔案不在其中；每個 source path（包括由別名網址渲染出的）都對應到它的項目；查詢表上每個 not-found 路徑都得到所寫的結果，且都不丟例外；新增或移除頁面後清單跟著變，`pnpm dev` 下在重新啟動後跟著變。（P1–P5、P7）
- **AC-2** 冷載入的決策，對決策表 A1–A5 的每一列（該列列出的每個儲存值 × 題目與文章 × base `/` 與 `/repo/`），導向或停留、顯示那一行與否、寫入偏好與否，都完全照該列；轉址前往清單項目，保留 base、query 與 hash，並使用 `replace`；轉址與那一行都等解題紀錄沿用確認做出決定。（A1–A7）
- **AC-3** 語系切換按鈕每次選擇都寫入；在頁面上、對應頁在清單內時導覽過去；不在時不導覽、不新增瀏覽紀錄、不改網址與介面語系，並立刻以所選語系顯示那一行，即使確認還沒做出決定；選單的標題是頁面語系，沒有那一行時只有一個選項、有那一行時有兩個，選頁面本身的語系會寫入並讓那一行消失；在找不到頁面的畫面上，前往存在的對應頁，否則只寫入；這些在 `MergedNav` 與預設主題的導覽列都成立，兩種 base 都成立；在 1280、1024、375 寬（第 8 階段，V3 與 V1l）三個內建翻譯選單都不出現，靜態 HTML 與 hydration 之後皆然；儲存寫不進去時不丟例外，選擇在這個分頁內有效。（B1–B7）
- **AC-4** 對應頁依查詢演算法有吻合的 not-found 抵達，由那個清單項目取代一次，保留 base、query 與 hash，並在落點頁以路徑所指的語系顯示那一行；沒有吻合時，以及查詢表上每個構造過的路徑，都顯示找不到頁面、不顯示那一行，結果都在同一個來源；載入失敗時顯示找不到頁面、不轉址；這些在冷載入與站內導覽都成立，轉址等確認的決定、那一行等落點頁的決定，不寫入任何偏好，按上一頁回到 not-found 路徑之前的頁面。（C1–C11）
- **AC-5** 那一行恰好在 L1 成立時出現，絕不出現在找不到頁面的畫面；冷載入或 not-found 抵達時在確認做出決定之後、語系切換時立刻出現；它的句子與連結文字逐字等於被要求語系的固定文字，`lang` 是字面值 `en` 或 `zh-TW`，連結前往所寫的清單並加上 base；題目頁上它是 `MergedNav` 之下、runtime 重置橫幅之上的橫幅，說明面板展開或收合都看得到；預設主題頁上它在 L4 指名的頂端 slot；每次抵達都重新判斷，只改 hash 或 query 的導覽不影響它，經由 S1 的轉址保留、轉址之後丟棄，沒有關閉控制，靜態 HTML 裡沒有它。（L1–L9）
- **AC-6** 用一份 fixture——一道已翻譯的題目、一道省略 `category` 的英文限定題目、一道只有繁中說明頁的題目、一道沒有號碼的題目——兩個語系的資料都含這四道，`id` 相同，`locale` 欄位照 schema；英文限定題目在繁中清單上的條目有英文的標題、摘要與網址，缺漏的分類為 `綜合`，帶 `lang="en"` 與標記 `只有英文`；反向的條目顯示 `Traditional Chinese only` 且沒有短連結；標記出現在清單檢視、格狀檢視與首頁的最新題目卡片，靜態 HTML 就已帶著；首頁計數包含四道；搜尋、篩選與已解題徽章在借來的條目上都有效；沒有號碼的條目沒有短連結。（E1–E10）
- **AC-7** helper 與複製按鈕在兩種模式、兩種語系下，都恰好給出 F1–F7 所列的網址，包括未翻譯的條目；按鈕的標籤與狀態文字用清單或頁面的語系，不論連結是哪個語系；顯示文字照舊與網址相符；任何輸出都不含 `/zh/c/`，也不含前面沒有語系代碼的 `/c/` 路徑。（F1–F10）

## 測試決策

- 在 seam 上測外部行為：導向與偏好的決策，作為以網址、base、儲存值、頁面清單與 router 結果為輸入的純函式（S1）；頁面清單對照獨立的 oracle 與查詢表（S2）；那一行、清單與首頁作為元件（S3、S4）；連結 helper 與複製按鈕（S5）；產生器的輸出（S6）。不對內部狀態做斷言。
- 那一行的句子、連結文字與清單的標記，以逐字相等釘住，做法同 `SessionGate-truth.test.ts` 釘住解題紀錄沿用確認的文案。
- S4 的 fixture 含一道已翻譯的題目、一道沒有 `category` 的英文限定題目、一道只有繁中說明頁的題目、一道沒有號碼的題目，以及一篇英文限定的文章；S1 與 S2 沿用它的頁面。S6 只用前兩道題目，另外為只有繁中說明頁的題目準備獨立的 fixture（G9），因為產生器遇到沒有號碼的題目會丟例外。
- 〈被覆寫的契約〉點名的既有測試會隨本 epic 修改；第 6 階段確認每一處修改都是表上所寫的那一項，並拒絕表外任何測試的修改。
- 第 8 階段是瀏覽器表面（S7）：解題紀錄沿用確認的等待、hydration、隱藏的內建選單、route watcher，以及各主機處理 404 的方式，都位在單元測試的決策與學習者之間。
